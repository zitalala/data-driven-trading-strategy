Analytical problems I solved

Making the metrics measure the right thing

Statistics

Neither the mean nor the median tells the truth

Found
Theme and stock rankings swung with a handful of extreme moves.
Cause
A mean is pulled by outliers; a median ignores them, though those stocks often matter most.
Fix
Z-scores against each stock's own history and its theme peers, across timeframes. Extremes stay in, measured against normal volatility.
No theme data

Stocks don't come labelled by theme

Found
No free source maps stocks to themes like "AI infrastructure".
Cause
Themes only exist in ETF names and holdings.
Fix
Used AI to extract 100+ themes and sub-themes from ETF names, then mapped stocks through ETF holdings.
Theme measurement

A theme is its stocks, not its ETF

Found
ETF prices missed where money was moving inside a theme.
Cause
An ETF price follows one fund's fixed weights.
Fix
Measure each theme from its stocks' volume-weighted performance, then Z-score it against VOO and its own history.

One ranked view every morning

Themes ranked by real trading flow, and stocks ranked by how unusual their strength is, ready before the US market opens.

Warehouse conventions

Tables are named by rule, not by hand

Every table name is built from three parts: asset, timeframe and layer, for example stock_…_1w_…. Names are validated and set in one config file, so the whole schema can be renamed in one place.

Lessons from building it

Problems I hit, and what I changed

Data correctness

One stock split broke the monthly numbers

Found
BYND looked abnormal on monthly and longer charts only.
Cause
A stock split. Bars were aggregated first and adjusted after, mixing pre- and post-split prices.
Fix
Adjust every daily bar first, then resample and recompute, for every stock and timeframe.
Data quality

Hourly bars that didn't line up

Found
The first hourly bar mixed pre-market and regular trading.
Cause
The provider's hourly bars start on the hour; the US market opens at 9:30.
Fix
Rebuilt hourly bars from 30-minute bars; trend work moved to adjusted daily data.
Storage

A database that kept growing

Found
The DuckDB file kept growing after every run.
Cause
Repeated CREATE OR REPLACE left dead space.
Fix
Drop-then-create, with explicit checkpoints and vacuuming.
Reliability

Long downloads kept getting interrupted

Found
Full-market downloads of over an hour often stopped halfway.
Cause
Machine sleep, network errors and API rate limits.
Fix
Per-ticker and per-step checkpoints; a rerun picks up exactly where it stopped.
Design

Duplicate data across timeframes

Found
Separate weekly and monthly downloads created duplicate tables.
Cause
Each timeframe was pulled from the API on its own.
Fix
Build every longer bar from adjusted daily bars: one source, six consistent timeframes.
Maintainability

Notebooks that couldn't scale

Found
Adding ETFs meant copying stock code.
Cause
Config, API calls and logic were repeated across scripts.
Fix
Refactored into a package with shared config, one API client and reusable services, so stocks and ETFs run on the same code.
